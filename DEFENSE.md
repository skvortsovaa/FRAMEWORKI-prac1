# Разбор ПР2: SmartSpace Monitor

## 1. Что изменилось относительно ПР1

В ПР1 программа проверяла одну серверную. Её свойства хранились в отдельных
переменных. В ПР2 тот же сценарий применяется к нескольким помещениям;
появились меню, коллекции, модули, история и сохранение в JSON.
Классы пока не используются: это следующий этап проекта.

Порядок работы: `main()` → загрузка JSON → меню → вызов нужной функции →
вывод результата → сохранение изменённых данных → возврат в меню.

## 2. Список и словарь

Где: `rooms.py`, функция `add_room()`; примеры данных — `data/state.json`.

```python
room = {
    "id": room_id,
    "name": name.strip(),
    "floor": floor,
    "area": area,
    "sensor": {
        "id": f"SENS-{room_id:03d}",
        "active": True,
        "battery": 100,
    },
}
```

Словарь хранит пары «ключ — значение». `room["name"]` получает название,
а `room["sensor"]["battery"]` — заряд из вложенного словаря.
`strip()` убирает пробелы с краёв. `:03d` дополняет числовой ID нулями
до трёх знаков: 1 превращается в `001`.

```python
validate_room(room)
rooms.append(room)
return room
```

Сначала проверяем поля. Только корректный словарь добавляется в список.
`append()` изменяет список, а `return` возвращает добавленную запись.

## 3. Генерация ID

Где: `rooms.py`, `add_room()`.

```python
room_id = max((room["id"] for room in rooms), default=0) + 1
```

Выражение в скобках выдаёт существующие ID по одному. `max()` выбирает
наибольший, затем прибавляется 1. Для пустого списка `default=0`, поэтому
первый ID равен 1. Это надёжнее `len(rooms) + 1`, когда ID идут с пропусками.

## 4. Поиск, цикл и исключение

Где: `rooms.py`, `get_room()`.

```python
def get_room(rooms: list[dict], room_id: int) -> dict:
    """Найти помещение по ID или сообщить об ошибке."""
    for room in rooms:
        if room["id"] == room_id:
            return room
    raise ValueError(f"Помещение с ID {room_id} не найдено.")
```

`for` перебирает список. Совпадение ID завершает функцию через `return`.
Если цикл закончился без совпадений, возбуждается исключение `ValueError`.
Оно перехватывается в меню, поэтому приложение продолжает работу.

`list[dict]`, `int`, `-> dict` — аннотации типов входных данных и результата.
Они помогают читать код, но сами по себе не проверяют значения при запуске.
Строка в тройных кавычках — docstring, документация функции.

Поиск по части названия реализован отдельно, в `find_rooms()`: списковое
включение отбирает подходящие записи; `casefold()` убирает различия регистра.

## 5. Сортировка, lambda и генератор

Где: `rooms.py`, `sort_rooms()` и `iter_rooms_on_floor()`.

```python
return sorted(rooms, key=lambda room: room["area"])
```

`sorted()` создаёт новый упорядоченный список. `key` указывает, какое значение
сравнивать. `lambda` — короткая безымянная функция, получающая площадь записи.
Исходный порядок списка не меняется.

```python
for room in rooms:
    if room["floor"] == floor:
        yield room
```

`yield` делает функцию генератором: она выдаёт подходящие записи по одной,
приостанавливаясь после каждой. В меню `list(...)` собирает их в список
для вывода. `return` завершил бы функцию после первой найденной записи.

## 6. Как сохранён сценарий ПР1

Где: `monitoring.py`, `check_room()`, `analyze_metric()`, `get_room_status()`.

```python
if not available:
    return "НЕТ ДАННЫХ"
elif leak_detected:
    return "АВАРИЯ"
elif not temperature_normal or not humidity_normal:
    return "ПРЕДУПРЕЖДЕНИЕ"
else:
    return "НОРМА"
```

Порядок условий важен. Сначала проверяется наличие данных; затем протечка,
потому что она важнее отклонения микроклимата. Если протечки нет, достаточно
одного показателя вне нормы для предупреждения.

`check_sensor()` возвращает `active and battery > 0`. Если измерения
недоступны, случайные показания не генерируются. Вместо них хранится `None`:
нулевая температура означала бы настоящее измерение и вводила бы в заблуждение.

```python
temperature = analyze_metric(
    round(random.uniform(16.0, 28.0), 2), *TEMPERATURE_LIMITS,
)
```

`uniform()` моделирует температуру, `round(..., 2)` округляет её до анализа.
`TEMPERATURE_LIMITS` — кортеж `(18.0, 24.0)`. Звёздочка передаёт два его
элемента отдельными аргументами `minimum` и `maximum`.
`analyze_metric()` возвращает словарь: значение, границы, признак нормы,
направление и размер отклонения. Общая функция используется и для влажности.

Внутри нормы отклонение считается от середины диапазона, вне нормы —
от ближайшей границы. Для влажности отклонение внутри нормы не выводится.
Низкий заряд отражается как обслуживание, а не как авария помещения.

ID отчёта формируется с `uuid4()`, чтобы повторные проверки получали разные
идентификаторы. Дата переводится в строку через `isoformat()`: JSON не умеет
напрямую хранить объект `datetime`.

## 7. Обработка нескольких помещений

Где: `main.py`, ветка пунктов 7 и 8 в `perform_action()`.

```python
for room in selected:
    report = check_room(room)
    data["reports"].append(report)
    show_report(report)
```

В пункте 7 `selected` содержит одно выбранное помещение; в пункте 8 — все.
Цикл выполняет один и тот же сценарий для каждой записи, затем добавляет
отчёт в список истории. `check_room()` занимается проверкой, `show_report()`
— выводом. История хранит результаты, а не пересчитывает их при просмотре.

## 8. JSON и with

Где: `storage.py`, `load_data()` и `save_data()`.

```python
with filename.open("r", encoding="utf-8") as file:
    data = json.load(file)
```

`with` — контекстный менеджер: открывает файл и закрывает его при выходе
из блока, в том числе при исключении. `json.load()` превращает содержимое
JSON в словари и списки Python.

```python
with temporary.open("w", encoding="utf-8") as file:
    json.dump(data, file, ensure_ascii=False, indent=2, allow_nan=False)
    file.write("\n")
temporary.replace(filename)
```

`json.dump()` выполняет обратное преобразование. `ensure_ascii=False`
оставляет читаемые русские буквы, `indent=2` задаёт отступы,
`allow_nan=False` запрещает специальные числа, недопустимые в обычном JSON.
После успешной записи временный файл заменяет основной.

Отсутствие файла означает новый пустой проект. Повреждённый JSON означает
ошибку: приложение сообщает о ней, а не заменяет существующий файл пустым.
`validate_data()` дополнительно проверяет структуру коллекций и ID помещений.
Множество `set()` помогает обнаружить повторяющиеся ID.

## 9. Меню, ошибки и сохранение

Где: `main.py`, `main()`; повтор числового ввода — `utils.py`.

```python
candidate = deepcopy(data)
if perform_action(choice, candidate):
    save_data(DATA_FILE, candidate)
    data = candidate
    print("Изменения сохранены.")
```

`deepcopy()` копирует не только внешний словарь, но и вложенные списки
и словари. Обычная поверхностная копия оставила бы вложенные объекты общими.
Действие работает с копией. Текущие данные заменяются только после успешного
сохранения. `perform_action()` возвращает `True` для действий, меняющих данные,
и `False` для просмотра, поиска и сортировки.

`while True` повторяет меню. `break` завершает цикл при выборе 0.
`except (ValueError, OSError)` перехватывает ошибки значений и файлов.
`EOFError` и `KeyboardInterrupt` позволяют закончить работу при прекращении
ввода или Ctrl+C. Изменения сохраняются после каждого успешного действия.

В `utils.py` вызов `int(input(prompt))` может дать `ValueError`: тогда
показывается сообщение и `while` повторяет ввод. Для дробного числа запятая
заменяется точкой; бесконечности и `NaN` отклоняются.

## 10. Тесты и линтер

Где: каталог `tests/`; простой пример — `test_rooms.py`.

```python
def test_find_rooms_ignores_case():
    rooms = []
    room = add_room(rooms, "Серверная", 3, 25.5)
    assert find_rooms(rooms, "СЕРВ") == [room]
```

Тест создаёт известные исходные данные, вызывает функцию и сравнивает
результат с ожидаемым. `assert` завершает тест ошибкой, если условие ложно.
pytest находит функции с префиксом `test_` в файлах `test_*.py`.
`pytest.mark.parametrize` повторяет один тест для нескольких наборов данных.
`patch()` подменяет случайную генерацию известными значениями, чтобы тест
давал одинаковый результат каждый раз. `tmp_path` предоставляет временную
папку для проверки JSON без изменения данных приложения.

Тесты проверяют поведение. flake8 проверяет оформление, неиспользуемые
импорты и другие замечания к коду. Успешный линтер ничего не выводит.
Команды установки и проверки приведены в README.
