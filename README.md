# SmartSpace Monitor

**Сервис мониторинга показателей помещений**

## Назначение проекта
Автоматизация сбора, хранения, анализа и визуализации данных о состоянии окружающей среды в закрытых пространствах. Сервис предназначен для обеспечения комфортных, безопасных и энергоэффективных условий, а также для своевременного предотвращения аварийных ситуаций (например, протечек, задымлений или выхода микроклимата за пределы нормы).

## Целевая аудитория
* **Facility-менеджеры и управляющие недвижимостью:** для контроля состояния офисных центров, ТЦ и жилых комплексов.
* **Администраторы специализированных помещений:** серверных, лабораторий, складов (в т.ч. холодильных), архивов.
* **Владельцы «умных домов» и квартир:** для поддержания идеального микроклимата и контроля безопасности.
* **Службы эксплуатации и технического обслуживания:** для мониторинга работоспособности оборудования и датчиков.

## Описание предметной области
Предметная область охватывает процессы контроля микроклимата и технических параметров в помещениях. Она включает в себя физический уровень (IoT-датчики, передающие телеметрию), уровень сбора данных (шлюзы, брокеры сообщений) и аналитический уровень (интерпретация данных, настройка пороговых значений, реагирование на отклонения). 

Контроль таких параметров, как температура, влажность, уровень CO2, освещенность и качество воздуха, критически важен для здоровья людей, сохранности имущества (например, на складах) и оптимизации энергопотребления зданий.

## Основные сущности
В основе архитектуры системы лежат следующие сущности:

1. **Помещение (Room)**
   * Физическое пространство (комната, офис, серверная, склад).
   * *Атрибуты:* название, тип назначения, площадь, этаж, координаты на плане.
2. **Датчик (Sensor)**
   * Аппаратное устройство, установленное в помещении для сбора данных.
   * *Атрибуты:* уникальный ID, серийный номер, тип подключения, статус (активен/неактивен/ошибка), уровень заряда батареи, привязка к помещению.
3. **Показатель (Metric)**
   * Тип измеряемой физической величины (справочник).
   * *Атрибуты:* название (например, "Температура", "Влажность", "CO2"), единица измерения (°C, %, ppm), минимальное и максимальное пороговое значение (норма).
4. **Значение (Value / Reading)**
   * Конкретное измерение, полученное от датчика в определенный момент времени.
   * *Атрибуты:* временная метка (timestamp), числовое значение, статус (в норме / предупреждение / критично), привязка к датчику и показателю.

## Текущая версия — четыре сущности и разделение по папкам

Консольная учебная симуляция мониторинга нескольких помещений.
Показания генерируются случайно; подключения к реальному оборудованию нет.
Реализованы четыре самостоятельные сущности со своими модулями,
JSON-коллекциями, проверками и тестами. Записи пока представлены словарями,
а операции — функциями, как в ПР2; переход к классам не требуется для запуска.
Перечень атрибутов выше описывает полный сервис; ниже — реализованные поля.

| Сущность | Модуль | Поля и назначение |
| --- | --- | --- |
| Помещение | `models/rooms.py` | `id`, `name`, `floor`, `area`; добавление, поиск, сортировка, фильтр этажа |
| Датчик | `models/sensors.py` | `id`, `room_id`, `active`, `battery`; создание и изменение состояния |
| Показатель | `models/metrics.py` | `id`, `name`, `unit`, `minimum`, `maximum`; справочник и изменение нормы |
| Измерение | `models/readings.py` | `id`, `sensor_id`, `metric_id`, `report_id`, `measured_at`, `value`, `minimum`, `maximum`, `status`; запись и поиск истории |

Связи: помещение → датчик → измерения ← показатель.
В текущей версии у помещения один комбинированный датчик температуры,
влажности и протечки. При добавлении помещения он создаётся автоматически.
Отчёты проверок дополнительно сохраняются в `reports.json`; каждое измерение
ссылается на свой отчёт. ID уникальны внутри соответствующих коллекций.

### Меню

1. Показать помещения с состоянием датчиков.
2. Добавить помещение и его датчик.
3. Найти помещения по части названия.
4. Отсортировать помещения по площади.
5. Отобрать помещения на этаже.
6. Изменить активность и заряд датчика помещения.
7. Проверить одно помещение.
8. Проверить все помещения.
9. Показать историю отчётов.
10. Показать отдельный список датчиков.
11. Показать справочник показателей и текущие нормы.
12. Изменить норму температуры или влажности по ID показателя.
13. Показать измерения датчика выбранного помещения от новых к старым.

Пункт 0 завершает программу. ID показателей: `temperature`, `humidity`,
`leak`. Для протечки 0 означает отсутствие, 1 — обнаружение; норма 0
фиксирована. Учебные начальные нормы: 18–24 °C и 40–60%.
Границы включены в норму. Это демонстрационные пороги, не универсальные
нормативы. Изменения порогов действуют только для следующих проверок:
измерения и отчёты хранят снимок нормы на момент получения данных.

Статусы: **НОРМА**, **ПРЕДУПРЕЖДЕНИЕ**, **АВАРИЯ**, **НЕТ ДАННЫХ**.
Протечка имеет приоритет над отклонениями микроклимата. Отключённый или
разряженный датчик не создаёт измерений; отчёт получает НЕТ ДАННЫХ.
Заряд ниже 20% вызывает рекомендацию обслуживания, но не меняет статус.
Отклонение влажности выводится в процентных пунктах, температуры — в °C.

### Сохранение и перенос данных

Каждый активный JSON-файл содержит список соответствующих записей.
Пути вычисляются относительно `main.py`, независимо от папки запуска.
Данные сохраняются после добавления помещения, изменения датчика или
порогов, а также после проверки помещений. Просмотр ничего не меняет.

Если отдельных файлов ещё нет, `load_data()` читает прежний `state.json`,
выделяет датчики и восстанавливает измерения из истории. Первый успешный
вызов сохранения записывает отдельные коллекции. Исходный `state.json`
остаётся без изменений и после переноса не используется при наличии
новых файлов. В поставляемых данных перенос уже выполнен.

При полном отсутствии данных создаётся пустой проект со справочником
показателей. При повреждённом JSON, неполном наборе файлов или нарушенных
связях программа сообщает об ошибке и не подменяет данные пустыми.

Запись выполняется через временные файлы с резервным журналом
`.save-backup.json`. При ошибке восстанавливается предыдущее состояние;
после прерывания процесса восстановление выполняется при следующей
загрузке. Если восстановление само не удалось, журнал сохраняется для
повторной попытки. Удалять его вручную во время восстановления не нужно.
Изменения в памяти принимаются только после успешного сохранения.
Программа рассчитана на один запущенный экземпляр; одновременная запись
несколькими процессами не поддерживается.

### Установка и запуск в Windows PowerShell

Требуется Python 3.10 или новее. Из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если окружение уже создано, достаточно последней команды.
Приложение использует стандартную библиотеку; pytest и flake8 нужны
только для разработки. При наличии команды `py` можно создать окружение
через `py -3 -m venv .venv`.

### Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 .
```

Тесты проверяют четыре сущности, правила мониторинга, сохранение связей,
перенос старой истории, откат при ошибках записи, восстановление после
прерывания и полный сценарий меню с повторным запуском. Файловые тесты
используют временные папки и не меняют данные проекта.

Сценарий для демонстрации: пункты 1, 10 и 11 показывают справочники;
пункт 7 создаёт отчёт и три измерения; пункт 13 показывает измерения.
Измените пороги через пункт 12, повторите проверку и убедитесь, что старые
измерения сохранили прежние границы. Отключите датчик через пункт 6:
новая проверка даст НЕТ ДАННЫХ. Перезапустите приложение и откройте историю.

Разбор кода для защиты находится в [DEFENSE.md](DEFENSE.md).

## Основные функции полного сервиса (планируются)

Следующие возможности описывают развитие учебной версии ПР2 до полного сервиса.
* **Управление объектами:** расширенное редактирование и иерархическая структура помещений.
* **Мониторинг оборудования:** подключение реальных датчиков и отслеживание их статуса в реальном времени.
* **Сбор и визуализация данных:** автоматический сбор показателей и построение исторических графиков (дашборды).
* **Система алертинга:** настройка пороговых значений и отправка уведомлений (Telegram, Email, SMS) при выходе показателей за пределы нормы или потере связи с датчиком.
* **Аналитика и отчетность:** формирование сводных отчетов по соблюдению норм микроклимата за выбранный период.
* **API и интеграции:** предоставление REST/MQTT API для приема данных со сторонних устройств и выгрузки в внешние системы.

## План развития проекта

### Этап 1: MVP (Минимально жизнеспособный продукт)
* Реализация базы данных и базового CRUD для основных сущностей.
* Настройка приема телеметрии по API / MQTT.
* Простой веб-интерфейс для просмотра списка помещений и текущих значений с датчиков.

### Этап 2: Аналитика и Уведомления
* Внедрение ролевой модели пользователей (Администратор, Оператор, Гость).
* Построение интерактивных графиков и дашбордов.
* Реализация движка правил для отправки алертов при отклонениях.

### Этап 3: Интеграции и Автоматизация
* Разработка открытых API и Webhooks для интеграции со сторонними системами.
* Внедрение сценариев автоматического реагирования (например, отправка команды на включение вентиляции при высоком уровне CO2).

### Этап 4: Продвинутая аналитика и Мобильность
* Выпуск мобильного приложения (iOS / Android) для push-уведомлений и быстрого доступа.
* Добавление предиктивной аналитики (прогнозирование выхода датчиков из строя, анализ энергоэффективности помещений на основе ML-моделей).
