# SmartSpace Monitor

**Сервис мониторинга показателей помещений**

## Назначение проекта
Автоматизация сбора, хранения, анализа и визуализации данных о состоянии окружающей среды в закрытых пространствах. Сервис предназначен для обеспечения комфортных, безопасных и энергоэффективных условий, а также для своевременного предотвращения аварийных ситуаций (например, протечек, задымлений или выхода микроклимата за пределы нормы).

## Целевая аудитория
* **Facility-менеджеры и управляющие недвижимостью:** для контроля состояния офисных центров, ТЦ и жилых комплексов.
* **Администраторы специализированных помещений:** серверных, лабораторий, складов (в т.ч. холодильных), архивов.
* **Владельцы «умных домов» и квартир:** для поддержания идеального микроклимата и контроля безопасности.
* **Службы эксплуатации и технического обслуживания:** для мониторинга работоспособности оборудования и датчиков.

## Описание предметной области
Предметная область охватывает процессы контроля микроклимата и технических параметров в помещениях. Она включает в себя физический уровень (IoT-датчики, передающие телеметрию), уровень сбора данных (шлюзы, брокеры сообщений) и аналитический уровень (интерпретация данных, настройка пороговых значений, реагирование на отклонения). 

Контроль таких параметров, как температура, влажность, уровень CO2, освещенность и качество воздуха, критически важен для здоровья людей, сохранности имущества (например, на складах) и оптимизации энергопотребления зданий.

## Основные сущности
В основе архитектуры системы лежат следующие сущности:

1. **Помещение (Room)**
   * Физическое пространство (комната, офис, серверная, склад).
   * *Атрибуты:* название, тип назначения, площадь, этаж, координаты на плане.
2. **Датчик (Sensor)**
   * Аппаратное устройство, установленное в помещении для сбора данных.
   * *Атрибуты:* уникальный ID, серийный номер, тип подключения, статус (активен/неактивен/ошибка), уровень заряда батареи, привязка к помещению.
3. **Показатель (Metric)**
   * Тип измеряемой физической величины (справочник).
   * *Атрибуты:* название (например, "Температура", "Влажность", "CO2"), единица измерения (°C, %, ppm), минимальное и максимальное пороговое значение (норма).
4. **Значение (Value / Reading)**
   * Конкретное измерение, полученное от датчика в определенный момент времени.
   * *Атрибуты:* временная метка (timestamp), числовое значение, статус (в норме / предупреждение / критично), привязка к датчику и показателю.

## Начальная версия — практическая работа №1

Реализован один законченный сценарий: **проверка состояния серверной и вывод отчёта**.
Программа моделирует комбинированный датчик температуры, влажности и протечки.
При каждом запуске выполняется одна проверка, а показания генерируются случайно.
Это учебная симуляция: подключения к реальному оборудованию и отправки уведомлений нет.

### Реализованные функции

* Вывод сведений о помещении и датчике.
* Проверка подключения и заряда батареи; при заряде ниже 20% — предупреждение об обслуживании.
* Отказ от генерации и анализа измерений при отключённом датчике или нулевом заряде.
* Проверка температуры и влажности, расчёт величины отклонений от заданных порогов.
* Обнаружение имитируемой протечки с приоритетом аварийного статуса.
* Итоговый отчёт с датой, временем, идентификатором и рекомендациями по каждому показателю.
* Проверка площади, диапазона заряда и порядка пороговых значений.

Возможные статусы помещения: **НОРМА**, **ПРЕДУПРЕЖДЕНИЕ**, **АВАРИЯ**, **НЕТ ДАННЫХ**.
Границы диапазонов включены в норму. Низкий заряд отражается отдельно от состояния помещения.
Температура 18–24 °C и влажность 40–60% — демонстрационные настройки, а не универсальные нормативы.
Отклонение влажности указывается в процентных пунктах.

### Соответствие требованиям ПР1

* Простые типы: `str` (названия, статусы), `int` (этаж, заряд), `float` (площадь, показания), `bool` (активность, протечка).
* Операции: арифметика, сравнения, `and`, `or`, `not`, конкатенация и повторение строк.
* Явное преобразование типов: `str()` при формировании идентификатора отчёта.
* Ветвления: `if`, `elif`, `else` для проверки датчика и анализа показаний.
* Импорт стандартных модулей: `datetime`, `random`.
* Пользовательские функции `def` с параметрами и возвращаемыми значениями.

Списки, словари, классы и циклы не используются. Сущности представлены отдельными переменными.
Сложные структуры данных предполагается добавить в ПР2.

### Функции в коде

* `validate_settings()` — проверка исходных настроек.
* `print_room_info()` — вывод сведений о помещении и времени проверки.
* `check_sensor()` — проверка датчика; возвращает его доступность (`bool`).
* `analyze_temperature()` и `analyze_humidity()` — анализ показаний и вывод рекомендаций; возвращают соответствие норме (`bool`).
* `get_room_status()` — определение итогового статуса помещения (`str`).
* `print_report()` — вывод итогового отчёта и рекомендаций по обслуживанию.
* `main()` — запуск полного сценария.

При импорте модуля проверка помещения не запускается: вызов `main()` защищён условием
`if __name__ == "__main__":`.

### Запуск в Windows PowerShell

Требуется Python 3.10 или новее. Откройте терминал в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe main.py
```

Если Python доступен через команду `py`, используйте `py -3 -m venv .venv`.
Активация окружения необязательна: команда выше явно запускает его интерпретатор.

### Проверка сценариев

Настройки находятся в начале `main.py`. Для проверки недоступности установите
`sensor_active = False`, для разряженной батареи — `sensor_battery_level = 0`,
для предупреждения о заряде — `sensor_battery_level = 15`.

Для воспроизводимой проверки можно временно заменить выражения генерации
`current_temperature`, `current_humidity` и `leak_detected` внутри ветки
`if sensor_available:` функции `main()` конкретными значениями:

| Температура | Влажность | Протечка | Ожидаемый статус |
| --- | --- | --- | --- |
| `21.0` | `50.0` | `False` | НОРМА |
| `18.0` | `40.0` | `False` | НОРМА — нижние границы |
| `24.0` | `60.0` | `False` | НОРМА — верхние границы |
| `16.0` | `50.0` | `False` | ПРЕДУПРЕЖДЕНИЕ — низкая температура |
| `28.0` | `75.0` | `False` | ПРЕДУПРЕЖДЕНИЕ — оба показателя выше нормы |
| `21.0` | `30.0` | `False` | ПРЕДУПРЕЖДЕНИЕ — низкая влажность |
| `21.0` | `50.0` | `True` | АВАРИЯ — протечка |

При недоступном датчике статус всегда **НЕТ ДАННЫХ**, измерения не выполняются.
После ручной проверки верните исходные настройки и случайную генерацию.

## Основные функции полного сервиса (планируются)

Следующие возможности описывают целевой сервис и пока не реализованы в версии ПР1.
* **Управление объектами:** добавление, редактирование и иерархическая структура помещений.
* **Мониторинг оборудования:** отслеживание статуса датчиков в реальном времени (онлайн/оффлайн, уровень сигнала, заряд батареи).
* **Сбор и визуализация данных:** отображение текущих показателей и построение исторических графиков (дашборды).
* **Система алертинга:** настройка пороговых значений и отправка уведомлений (Telegram, Email, SMS) при выходе показателей за пределы нормы или потере связи с датчиком.
* **Аналитика и отчетность:** формирование сводных отчетов по соблюдению норм микроклимата за выбранный период.
* **API и интеграции:** предоставление REST/MQTT API для приема данных со сторонних устройств и выгрузки в внешние системы.

## План развития проекта

### Этап 1: MVP (Минимально жизнеспособный продукт)
* Реализация базы данных и базового CRUD для основных сущностей.
* Настройка приема телеметрии по API / MQTT.
* Простой веб-интерфейс для просмотра списка помещений и текущих значений с датчиков.

### Этап 2: Аналитика и Уведомления
* Внедрение ролевой модели пользователей (Администратор, Оператор, Гость).
* Построение интерактивных графиков и дашбордов.
* Реализация движка правил для отправки алертов при отклонениях.

### Этап 3: Интеграции и Автоматизация
* Разработка открытых API и Webhooks для интеграции со сторонними системами.
* Внедрение сценариев автоматического реагирования (например, отправка команды на включение вентиляции при высоком уровне CO2).

### Этап 4: Продвинутая аналитика и Мобильность
* Выпуск мобильного приложения (iOS / Android) для push-уведомлений и быстрого доступа.
* Добавление предиктивной аналитики (прогнозирование выхода датчиков из строя, анализ энергоэффективности помещений на основе ML-моделей).
