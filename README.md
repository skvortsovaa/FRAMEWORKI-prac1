# SmartSpace Monitor

**Сервис мониторинга показателей помещений**

## Назначение проекта
Автоматизация сбора, хранения, анализа и визуализации данных о состоянии окружающей среды в закрытых пространствах. Сервис предназначен для обеспечения комфортных, безопасных и энергоэффективных условий, а также для своевременного предотвращения аварийных ситуаций (например, протечек, задымлений или выхода микроклимата за пределы нормы).

## Целевая аудитория
* **Facility-менеджеры и управляющие недвижимостью:** для контроля состояния офисных центров, ТЦ и жилых комплексов.
* **Администраторы специализированных помещений:** серверных, лабораторий, складов (в т.ч. холодильных), архивов.
* **Владельцы «умных домов» и квартир:** для поддержания идеального микроклимата и контроля безопасности.
* **Службы эксплуатации и технического обслуживания:** для мониторинга работоспособности оборудования и датчиков.

## Описание предметной области
Предметная область охватывает процессы контроля микроклимата и технических параметров в помещениях. Она включает в себя физический уровень (IoT-датчики, передающие телеметрию), уровень сбора данных (шлюзы, брокеры сообщений) и аналитический уровень (интерпретация данных, настройка пороговых значений, реагирование на отклонения). 

Контроль таких параметров, как температура, влажность, уровень CO2, освещенность и качество воздуха, критически важен для здоровья людей, сохранности имущества (например, на складах) и оптимизации энергопотребления зданий.

## Основные сущности
В основе архитектуры системы лежат следующие сущности:

1. **Помещение (Room)**
   * Физическое пространство (комната, офис, серверная, склад).
   * *Атрибуты:* название, тип назначения, площадь, этаж, координаты на плане.
2. **Датчик (Sensor)**
   * Аппаратное устройство, установленное в помещении для сбора данных.
   * *Атрибуты:* уникальный ID, серийный номер, тип подключения, статус (активен/неактивен/ошибка), уровень заряда батареи, привязка к помещению.
3. **Показатель (Metric)**
   * Тип измеряемой физической величины (справочник).
   * *Атрибуты:* название (например, "Температура", "Влажность", "CO2"), единица измерения (°C, %, ppm), минимальное и максимальное пороговое значение (норма).
4. **Значение (Value / Reading)**
   * Конкретное измерение, полученное от датчика в определенный момент времени.
   * *Атрибуты:* временная метка (timestamp), числовое значение, статус (в норме / предупреждение / критично), привязка к датчику и показателю.

## Текущая версия — практическая работа №2

Консольное приложение продолжает сценарий ПР1: проверяет температуру,
влажность и протечку. Теперь можно работать с несколькими помещениями,
менять состояние датчиков и сохранять историю проверок между запусками.
Это учебная симуляция: показания генерируются случайно, подключения
к реальному оборудованию и отправки уведомлений нет.

### Возможности

- Просмотр, добавление и поиск помещений по части названия.
- Сортировка по площади и отбор помещений на заданном этаже.
- Изменение активности датчика и заряда батареи.
- Проверка одного помещения (развитие сценария ПР1) или всех помещений.
- Расчёт отклонений температуры и влажности, рекомендации, проверка протечки.
- Просмотр краткой истории проверок от новых к старым.
- Автоматическая загрузка и сохранение помещений и результатов в JSON.
- Обработка ошибочного ввода, неизвестного ID и ошибок файлов.

Статусы: **НОРМА**, **ПРЕДУПРЕЖДЕНИЕ**, **АВАРИЯ**, **НЕТ ДАННЫХ**.
Протечка имеет приоритет над отклонениями микроклимата. Если датчик
неактивен или разряжен, показания не генерируются, статус — НЕТ ДАННЫХ.
Низкий заряд (меньше 20%) требует обслуживания, но сам по себе не меняет
статус помещения. Границы нормы включены в допустимый диапазон.

Пороги в `monitoring.py`: 18–24 °C и 40–60%. Это демонстрационные значения,
а не универсальные нормативы. Отклонение влажности указывается в процентных
пунктах; отклонение температуры внутри нормы — от середины диапазона.

### Структура проекта

```text
FRAMEWORKI-prac1/
├── main.py              # меню, вызовы функций, вывод результатов
├── rooms.py             # добавление, поиск, сортировка, проверка помещений
├── monitoring.py        # измерения и анализ по правилам ПР1
├── storage.py           # чтение, проверка и запись JSON
├── utils.py             # ввод чисел с повтором при ошибке
├── data/state.json      # помещения и история проверок
├── tests/               # тесты помещений, мониторинга и файлов
├── pytest.ini           # настройки поиска тестов и импорта модулей
├── .flake8              # исключение виртуального окружения из проверки
├── requirements.txt     # инструменты разработки: pytest и flake8
├── DEFENSE.md           # разбор кода и сценарий защиты
└── README.md
```

### Структуры данных

Корень `state.json` — словарь с двумя списками: `rooms` и `reports`.
Каждое помещение — словарь с `id`, `name`, `floor`, `area` и вложенным
словарём `sensor` (`id`, `active`, `battery`). ID связывает отчёт с помещением.
Отчёт содержит время, снимок состояния датчика, результаты анализа и статус.
Отсутствующее показание хранится как `None` в Python и `null` в JSON.

Поставляются два примера: серверная из ПР1 и архив. История изначально пуста.
Если файл отсутствует, приложение открывает пустой проект: добавьте помещение
через пункт 2. При повреждённом JSON или неверной структуре программа сообщает
об ошибке и завершает работу, сохраняя исходный файл для исправления.

Данные сохраняются после добавления помещения, изменения датчика и проверок.
При ошибке сохранения действие не применяется к текущим данным в памяти.
Запись выполняется через временный файл с последующей заменой основного.
Путь вычисляется относительно `main.py`, поэтому запуск из другой папки
не создаёт отдельную базу. Это локальная учебная программа для одного
запущенного экземпляра; одновременная запись из нескольких процессов
не предусмотрена.

благодаря условию `if __name__ == "__main__":`.

### Установка и запуск в Windows PowerShell

Требуется установленный Python 3.10 или новее. В папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Если Python доступен через `py`, первую команду можно заменить на
`py -3 -m venv .venv`. Активация окружения необязательна.
Приложение использует стандартную библиотеку; pytest и flake8 нужны
только для тестирования и проверки оформления.

### Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 .
```

При активированном окружении эквивалентные команды — `pytest` и `flake8`.
Успешный flake8 ничего не выводит. Тесты покрывают добавление и поиск,
сортировку, границы нормы, приоритет аварии, недоступный датчик,
некорректные данные и сохранение JSON. Файловые тесты используют временные
папки и не меняют `data/state.json`.

Для ручной проверки выберите пункт 7 и ID 1. Затем в пункте 6 отключите
датчик и повторите проверку: ожидается НЕТ ДАННЫХ. Включите его обратно,
задайте заряд 15% и проверьте предупреждение об обслуживании. Через пункт 8
проверьте все помещения, через 9 — историю. Выйдите и перезапустите
приложение: история должна сохраниться. Результаты активного датчика
случайны; в тестах генерация заменена заранее известными значениями.

## Основные функции полного сервиса (планируются)

Следующие возможности описывают развитие учебной версии ПР2 до полного сервиса.
* **Управление объектами:** расширенное редактирование и иерархическая структура помещений.
* **Мониторинг оборудования:** подключение реальных датчиков и отслеживание их статуса в реальном времени.
* **Сбор и визуализация данных:** автоматический сбор показателей и построение исторических графиков (дашборды).
* **Система алертинга:** настройка пороговых значений и отправка уведомлений (Telegram, Email, SMS) при выходе показателей за пределы нормы или потере связи с датчиком.
* **Аналитика и отчетность:** формирование сводных отчетов по соблюдению норм микроклимата за выбранный период.
* **API и интеграции:** предоставление REST/MQTT API для приема данных со сторонних устройств и выгрузки в внешние системы.

## План развития проекта

### Этап 1: MVP (Минимально жизнеспособный продукт)
* Реализация базы данных и базового CRUD для основных сущностей.
* Настройка приема телеметрии по API / MQTT.
* Простой веб-интерфейс для просмотра списка помещений и текущих значений с датчиков.

### Этап 2: Аналитика и Уведомления
* Внедрение ролевой модели пользователей (Администратор, Оператор, Гость).
* Построение интерактивных графиков и дашбордов.
* Реализация движка правил для отправки алертов при отклонениях.

### Этап 3: Интеграции и Автоматизация
* Разработка открытых API и Webhooks для интеграции со сторонними системами.
* Внедрение сценариев автоматического реагирования (например, отправка команды на включение вентиляции при высоком уровне CO2).

### Этап 4: Продвинутая аналитика и Мобильность
* Выпуск мобильного приложения (iOS / Android) для push-уведомлений и быстрого доступа.
* Добавление предиктивной аналитики (прогнозирование выхода датчиков из строя, анализ энергоэффективности помещений на основе ML-моделей).
